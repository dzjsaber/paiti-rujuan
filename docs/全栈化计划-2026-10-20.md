# 拍题入卷 · 全栈化计划（第一期：云端备份）

> 状态：2026-10-20 已完成代码与本地验证；待真机联调，提交/推送待用户确认。
> 执行方式：新开对话，发送"读 docs/全栈化计划-2026-10-20.md，按计划执行"。

## 一、目标与定位

给现有 React Native 客户端加一个最小后端，实现**云端备份 / 恢复**（多设备迁移）。

- 真实需求驱动：换手机、平板与手机共用题库。
- 技术价值：REST API 设计、JWT 鉴权、数据版本化、错误处理与大小限制、服务端测试。
- 复用现有客户端备份体系：版本化 JSON、稳定 ID、`restoreBackup` 按 ID 合并——服务端只存 JSON，不解析题库。

## 二、明确不做（本期）

- 增量同步 / 冲突解决（第二期）
- AI 服务端代理（当前"用户自备 Key"更安全省钱）
- 题库社区 / 分享（需求文档明确不做）
- 付费/配额/邮箱验证（个人自用服务）

## 三、架构决策

- 后端放在**同仓库** `server/` 子目录（个人 monorepo，版本一致、便于联调）。
- **FastAPI + SQLAlchemy + SQLite**（后续换 Postgres 只需改 `DATABASE_URL`）。
- 认证：邮箱验证码（免密码），JWT（30 天）；验证码只存 HMAC 哈希并做发送限流，验证码与 token 不进日志。
- 服务端只保存**最新一份备份 JSON**（带版本号），不做题库级解析；客户端本地备份仍是最后防线。
- 客户端：新增"云端备份"页面，复用 `src/db/backup.ts` 的 `buildBackup / validateBackup / restoreBackup`（**零改动**）。

## 四、后端规格（server/）

目录：

```
server/
  app/
    main.py           FastAPI 实例、CORS（仅开发）
    db.py             SQLAlchemy engine/session（DATABASE_URL）
    models.py         User、Backup
    schemas.py        Pydantic 请求/响应模型
    auth.py           验证码哈希、JWT 签发/校验、get_current_user 依赖
    mailer.py         SMTP 发送登录验证码
    routers/
      auth.py         POST /api/auth/request-code, POST /api/auth/verify-code
      backup.py       PUT /api/backup, GET /api/backup
  tests/
    test_auth.py
    test_backup.py
  requirements.txt
  .env.example        DATABASE_URL=sqlite:///./paiti.db / JWT_SECRET=... / MAX_UPLOAD_MB=20
  README.md           启动、测试、部署说明
```

接口约定：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/auth/request-code` | `{email}`；发送 6 位验证码，10 分钟有效 |
| POST | `/api/auth/verify-code` | `{email, code}` → `{token}`；首次验证自动建号 |
| PUT | `/api/backup` | Bearer JWT；body 为备份 JSON（校验顶层 `app == "paiti-rujuan"` 与 `version`）；返回 `{version, updatedAt}` |
| GET | `/api/backup` | Bearer JWT；返回最近一次备份 JSON 原文；无备份 404 |
| GET | `/api/health` | `{ok: true}` |

约束与安全：

- 备份大小 ≤ 20MB（与客户端 `MAX_BACKUP_BYTES` 一致），超限 413。
- 用户隔离：任何备份读写都按当前 JWT 用户过滤（测试覆盖"用户 A 不能读用户 B"）。
- 验证码使用 HMAC-SHA256 存哈希、一次性使用；60 秒重发冷却、单码最多 5 次尝试、邮箱与 IP 小时限额。
- SMTP 授权码与 JWT 密钥来自环境变量（缺省值仅本地开发用，README 提示生产必须改）。
- 上传内容只做顶层字段校验，不解析题目（避免半解析造成的维护负担）。

## 五、客户端改动

新增 `src/screens/CloudBackupScreen.tsx`（从设置页"数据"分组进入）：

- 服务器地址输入（默认 `http://<局域网IP>:8000`，存 SecureStore；换设备可改）
- 未登录：邮箱 + 6 位验证码；首次验证自动建号
- 已登录：显示账号；按钮"上传当前备份"（`buildBackup` → PUT）、"从云端恢复"（GET → `validateBackup` → 确认 → `restoreBackup` 按 ID 合并）、"退出登录"
- 恢复前必须弹确认框并说明"按 ID 合并、不会覆盖本机已有数据"

新增 `src/services/cloud.ts`：fetch 封装（超时 30s、错误信息映射、Bearer 注入）。

`App.tsx`：导航加 `cloudbackup` 屏；`SettingsScreen` 数据分组加入口。

Token 存 SecureStore（`cloud_token`），服务器地址存 SecureStore（`cloud_server`）。

## 六、验收清单

1. 后端：`pytest` 全绿（验证码登录/首次建号/验证码复用、过期、错误、锁定/发送限流/鉴权失败/上传后下载一致/大小超限/用户隔离）；`uvicorn app.main:app` 本地启动，curl 冒烟。
2. 客户端：`npx tsc --noEmit` + 全部 `tests/*.verify.ts` 通过。
3. 真机联调（手机 APK/Expo Go 访问电脑局域网 IP）：
   邮箱验证码登录 → 上传备份 → 退出 → 重新登录 → 下载并合并恢复 → 题库数据一致；
   另测：错误验证码、服务器关闭时的可读错误提示。
4. 现有功能零回归（识别/刷题/讲解/本地备份照常）。

## 十、风险

- 同步语义仍是"最新备份覆盖式上传"：多设备同时上传会以最后一次为准（客户端恢复是按 ID 合并，不会丢本地数据；但云端只有一份历史）。第二期再解决。
- 局域网 IP 会变化：演示时需查当前 `Get-NetIPAddress` 后填地址。
- 服务端存有用户题库备份：仅用于个人/演示；公开部署前需说明数据范围（计划内不公开部署）。
