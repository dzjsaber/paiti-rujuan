## 一、目标

把现有 RAG 讲解升级为**带工具调用的 Agent**：模型自主决定检索教材 / 题库 / 错题，
多轮直到信息足够，过程实时可见，最终讲解带引用。

- 不引入 Python / LangGraph（RN 端不现实）；用 OpenAI 兼容 function calling + 自研轻量循环。
- 产品价值：讲解前自动查题库相似题与相关错题，减少"教材未覆盖"误判。
- 简历价值：Agent 循环、工具编排、失败回填、过程可视化（面试高频话题）。

## 二、范围（本期）

工具集只做 3 个（全部复用现有能力）：

1. `search_materials(query)`：教材检索（复用 `searchMaterialsSmart`；题库绑定时限定绑定教材）
2. `search_bank(query)`：题库相似题检索（复用 FTS5，限定当前题库、只读、最多 5 条摘要）
3. `get_related_wrong(question_id)`：当前题库错题中题干相近的前 5 条（错误次数 / 最近时间）

明确不做：

- 联网工具（保留现有"教材未命中 → 用户确认后联网/模型知识"的降级链，费用与确认语义不变）
- 保存工具（现有"讲解完成自动保存"逻辑在 Agent 结束后执行）
- 任意代码执行 / 文件工具（无需求、有安全风险）

## 三、技术设计

- `LLMService`：新增 `tools` 参数（OpenAI 工具协议）与 tool_calls 响应解析；
  回填消息使用 `role:"tool"` + `tool_call_id`。
  - 智谱、DeepSeek 官方接口均支持 tools；**自定义接口不保证** → 非智谱/DeepSeek 端点自动回退为单轮讲解。
- `core/agentLoop.ts`（纯逻辑，可离线单测）：最多 3 轮；
  模型返回 tool_calls → 逐个执行 → 回填 → 继续；达到上限强制总结；
  工具抛错时回填错误文本继续（不中断对话）。
- `core/agentTools.ts`：3 个工具的定义（name / description / parameters JSON Schema）与执行器。
- `PracticeScreen`：讲解入口不变；流式状态行显示工具调用过程（如"正在检索教材… 命中 3 条"）；
  最终讲解沿用现有卡片、自动保存与降级链。
- `prompts/ragExplain.ts` v3：在系统提示中说明可用工具与"仍须依据教材"的约束。

## 五、验收

1. 单测：多轮工具调用、工具失败回填、达到最大轮数、无工具调用直接回答；tsc 与全部既有测试通过。
2. 真机：绑定教材的库讲解 → 能看到工具调用过程 → 最终引用教材编号；
   教材未命中 → 仍弹"联网 / 模型知识"确认；未绑定教材的库 → 题库 / 错题工具可用或回退单轮。
3. 现有快速讲解行为零回归；APK 可演示。

## 六、工作量与风险

- 工作量：约 1.5~2 天（协议层 + 循环 + UI + 测试）。
- 风险：各提供商 function calling 返回格式差异（第一步先各实测一次再写循环）；
  工具调用会略增延迟（限 3 轮、工具轻量）；自定义接口无工具支持时自动降级（需在 UI 标注）。
